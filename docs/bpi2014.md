# Real data: BPI Challenge 2014 (Rabobank)

BankOps AI can load a small, curated subset of real IT service management data: the BPI Challenge
2014 logs from Rabobank Group ICT. The data is anonymised and covers incidents, their activity
history and changes, keyed by configuration items grouped into service components.

> van Dongen, B.F. (2014) *BPI Challenge 2014*. 4TU.ResearchData.
> doi:10.4121/uuid:c3e5d162-0cfd-4bb0-bd82-af5268819c35. Use is subject to the 4TU terms. The raw
> files and the converted subset are **not stored in git**; the script rebuilds the subset from the
> raw files.

## Run it

```powershell
# raw files (Detail_Incident.csv, Detail_Incident_Activity.csv, Detail_Change.csv) in data\raw\bpi2014
cd backend
.\.venv\Scripts\python.exe scripts\bpi2014_to_dataset.py --raw ..\data\raw\bpi2014 --out datasets\bpi2014
.\.venv\Scripts\python.exe -m app.ingestion validate datasets\bpi2014
.\.venv\Scripts\python.exe -m app.ingestion load datasets\bpi2014
```

Result: **6 applications, 300 incidents (P2-P4), 130 changes, 8 incident-to-change links**, tagged
`data_source = BPI2014`. Look for applications named `BPI-W000…` in the Incidents filter.

## What the subset contains

| BankOps | BPI 2014 source | Rule |
|---|---|---|
| Application | Service component (WBS) | The 6 components with the most incidents. Tier from the share of priority 1-3 incidents (top 2 = Tier 1, next 2 = Tier 2, rest Tier 3). |
| Incident | `Detail_Incident.csv` | Category "incident" only (no information requests), opened in March 2014. All priority 1-3 incidents and every incident with a related change are kept; priority 4-5 incidents are sampled with a fixed seed up to 300. |
| Severity | Priority | 1, 2, 3 → P1, P2, P3; 4 and 5 → P4. |
| Category | Closure code, then CI type | Software → Application; Hardware → Infrastructure; Data → Data processing; otherwise from the CI type (computer, storage → Infrastructure; database → Database). |
| History | `Detail_Incident_Activity.csv` | First *Assignment* (team = assignment group), Investigating, up to 4 reassignment / update notes, Resolved and Closed at the logged times. |
| Change | `Detail_Change.csv` | Changes on the same components implemented 15 Feb - 31 Mar 2014, plus any change an incident references. Risk: Minor / Business / Major Business → Low / Medium / High; the emergency flag → Emergency; "Standard…" types → Standard. |
| Change link | Incident "Related Change" | Linked as **Suspected**: the log records a relation, not a proven cause. |

BPI has no free-text descriptions, so titles and descriptions are built from the structured fields
(CI, type, impact, urgency, priority, knowledge article, reassignments, closure code). The March 2014
sample contains no P1s. A P1 would stay Resolved rather than Closed, because closing a P1 needs a
human-confirmed root cause and BPI does not record one.

## How it is used

- **Everyday screens:** the BPI incidents appear in the incident list, search, reports and AI
  analysis like any other. Reports cover the period you pick, and these incidents are from 2014, so
  they only show in the incident list and on their applications.
- **ML:** BPI is left out of ML training (it is from 2014 and has no free text) but receives
  predictions.
- **Tests:** `tests/test_bpi2014.py` checks the mapping on hand-made rows in the original file
  format, so the test suite does not need the raw files.
